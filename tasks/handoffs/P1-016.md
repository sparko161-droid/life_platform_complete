# Handoff — P1-016 Implement vertical slice API/client wiring and recovery states

## Goal
UI executes the real vertical slice and handles loading, retry, conflict
and rejected-proof states.

## Branches
- `agent/frontend-lead/p1-016-recovery-states` (merged, PR #55) — the
  recovery vocabulary and the screen-state mechanism.
- `agent/frontend-lead/p1-016-task-screen` — C-TASK, the screen where the
  slice is actually executed.

## Files changed
- `packages/ux-contracts/src/screens.ts` — `SCREENS` changed from an
  annotated `Record` to `as const satisfies Record<...>`, plus a
  `ScreenStates<Id>` helper. Without this the per-screen state unions
  were erased to `string` and nothing downstream could be checked.
- `packages/ui/src/screen-state.ts` — new. `defineScreenStates` binds a
  screen id to a complete map of its declared states; `screenStateGaps`
  is the runtime equivalent for the stale-`dist` case the types cannot
  see.
- `packages/ui/src/recovery.ts` — new. Error code → user-actionable
  recovery, with separate parent and child tables.
- `packages/ui/test/recovery.test.ts` — new.
- `apps/child-web/app/child/today/page.tsx` — C-TODAY rewritten as a
  state-driven screen; task cards now link to C-TASK.
- `apps/child-web/app/child/task/[id]/page.tsx` — new. C-TASK.

## Contracts changed
None in shape. `SCREENS` changed only in how its type is expressed —
same values, narrower inferred type.

## Tests run
Full local sweep on both branches: build → typecheck → test → knip → the
registry/control/contracts validators. CI green on PR #55.

## Decisions
- **Coverage is a compile error, not a checklist.** The P1-032 and
  P1-036 handoffs both recorded "declares states the pages do not
  render" as an open risk, twice, as a note. `defineScreenStates` is
  keyed on the screen's own literal state union, so an omitted state — or
  one the contract has since dropped — fails to build. A note that keeps
  recurring is a mechanism that is missing.
- **A child is never told to sign in.** ADR-0006 D3 gives a child no
  credentials, so "войдите снова" is advice they cannot follow. The
  child table maps every session failure to `ASK_ADULT`, and a test
  asserts `SIGN_IN` never appears on that surface.
- **A conflict is never retry-safe.** `CONFLICT` is always
  `retrySafe: false` + `REFRESH`, on both surfaces and in C-TASK's
  mutation path: repeating the request would apply a decision made
  against state that has since moved.
- **REJECTED stays distinct from FAILED** by routing state through the
  shared `deriveUiTaskState` rather than a hand-written mapping. Both
  currently render the same C-TASK state, but the distinction survives
  where the copy can diverge later.
- **Raw error codes are never shown.** An unmapped code falls back to
  generic copy; a test asserts the code does not appear in the message,
  and another asserts no Latin-script leakage — the same rule
  `@life/ui-language` enforces on `UI_STRINGS`.

## Known risks
- **Only the child surface is fully state-covered.** C-TODAY and C-TASK
  use `defineScreenStates`; the parent screens do not yet, so the
  original coverage risk still stands for them. The mechanism exists and
  is cheap to apply — this is remaining work, not a missing capability.
- **`FIRST_DAY` is unreachable in practice.** C-TODAY declares it and
  renders it, but nothing distinguishes a first day from any other empty
  day, so `NO_TASKS` wins. Either the contract or the data needs to
  decide which one is real.
- **Offline is detected, not handled.** Both screens read
  `navigator.onLine` and say so honestly; nothing is queued for replay.
  That is a deliberate scope line, not an oversight — offline write
  queueing is its own design problem.
- **No browser-level test asserts the rendering.** Coverage is enforced
  by the type system and by unit tests over the recovery table; there is
  no harness that drives these pages. P1-017's journey gates are where
  that belongs.
