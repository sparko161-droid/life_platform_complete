## Known risks
- No UI component tree exists yet (packages/ui is a Phase 1+ placeholder), so
  the lint currently only checks the canonical UI_STRINGS catalog seeded from
  docs/ux/ui-language.md's "Preferred wording" table, not real component
  source. `lintCatalog` is designed to run unchanged over real locale files
  once a localization system exists; a follow-up static check (hard-coded
  JSX string literal detection) is out of scope until there is JSX to check.

## Decisions
- Forbidden-term matching is case-insensitive, word-based (Latin-script
  tokenization), and does not double-report a matched forbidden term as a
  separate NON_CYRILLIC_TEXT violation.
- Brand exceptions are limited to what docs/ux/ui-language.md's "Exceptions"
  section literally allows in Latin script: "MAX" (Алиса/Телеграм are already
  Cyrillic in the doc, so they never trip the Latin-script check anyway).
