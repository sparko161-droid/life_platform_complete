# Handoff — P1-004 Child today/tasks UX

## Goal
Child sees assigned tasks, opens a task, starts an attempt and sees
deterministic state/recovery feedback.

## Branch
agent/frontend-lead/p1-004-child-tasks

## Files changed
- `services/api/src/http/task.controller.ts` — `/child/today` scope is
  now decided by the session, not the query (`resolveChildScope`).
- `services/api/src/repositories/task-repository.ts` —
  `listTodayCardsByChild` (joins the template for a title),
  `hasEverBeenAssigned`. `listActiveAssignmentsByChild` removed, since a
  card with no title cannot be rendered for a child.
- `services/api/openapi/openapi.yaml` 0.7.0 → 0.8.0. Client regenerated.
- `services/api/test/child-today.e2e.test.ts` — new, 9 tests.
- `apps/child-web/app/child/today/page.tsx` — C-TODAY rewritten.
- `apps/child-web/lib/today.ts` — new, state derivation and card copy.
- `apps/child-web/test/today.test.ts` — new, 11 tests.
- `apps/child-web/app/child/task/[id]/page.tsx` — dropped an unfounded
  `rejectedByParent: true`.
- `apps/child-web/package.json` — the app runs tests now.

## Contracts changed
**openapi 0.7.0 → 0.8.0.** All three changes are readable by an existing
client: `getChildToday`'s `childId` becomes optional (loosening), the
response gains `everHadTasks`, and its cards become `ChildTodayCard` — a
superset of `TaskAssignment` adding `title`, `rewardXp`, `rewardCoins`.

## Tests run
20 new tests. Full sweep: build → typecheck → test → knip →
`generate:check` → the three validators. The API tests skip locally
without a database and run against real Postgres in CI.

## Decisions
- **The session decides whose day is returned.** This is DISC-P1-004-1
  and the reason this task grew a backend half. `childId` was a query
  parameter used verbatim, so any child session could read any child's
  day — in any family — by editing the URL, while the contract said the
  view was scoped to the caller. A mismatch is **refused**, not silently
  corrected: substituting the right id would hide a client bug, and
  honouring the requested one is the vulnerability itself.
- **Unknown and other-family child ids fail identically.** Distinguishing
  them would turn the endpoint into a probe for which child ids are real.
- **The card carries the title.** A bare `TaskAssignment` has none, so
  the previous screen could only render `status` — and "SUBMITTED" in
  front of a seven-year-old is exactly what docs/ux/ui-language.md
  forbids. Joining server-side keeps one round trip and one consistent
  snapshot.
- **`everHadTasks` exists so `FIRST_DAY` can be reached.** C-TODAY
  declares both `FIRST_DAY` and `NO_TASKS`; they are identical in the
  data and mean very different things to a child. The P1-016 handoff
  recorded `FIRST_DAY` as unreachable; only the server can tell them
  apart, so it now says which.
- **A failed sync never renders as an empty day.** Showing `NO_TASKS`
  after a failed fetch would tell a child their tasks are gone — a
  different and much worse claim than "we could not check".
- **Cards show an invitation, not a status**, and an unrecognised status
  from a newer server still yields "Открыть" rather than nothing. No
  dead ends, including when the client is older than the server.
- **Dropped `rejectedByParent: true` from C-TASK.** I set it in P1-016;
  the assignment does not say who rejected it, so it asserted a fact the
  client does not have. The contract already defaults an ambiguous
  rejection to the more conservative framing.

## Known risks
- **DISC-P1-004-2 is open and is the same class of bug.**
  `GET /families/{familyId}` performs no membership check at all: any
  authenticated session can read any family by id, including children's
  names and birth years. Found while writing the membership check this
  task needed. Not fixed here — it is a different endpoint with its own
  callers, and it deserves a sweep of every family-scoped path rather
  than one endpoint at a time. Recorded HIGH.
- **C-TASK still shows no task title.** `getTaskAssignment` returns a
  bare `TaskAssignment`, so the detail screen says "Задание". The same
  fix as the today card applies and was left out to keep this change
  reviewable.
- **`streak` is still absent** from the today view. It is in the screen
  doc's data list and in the schema as optional; progression is not
  implemented, and a fabricated default would be worse than its absence.
- **No accessibility audit was run**, though the test strategy names
  one. Touch targets are `min-h-11`, the page uses a labelled section
  and `aria-busy`, and copy is checked for Latin-script leakage — none
  of that is an audit. P1-017 owns it.
- **Rewards on the card are carried but not displayed.** They are in the
  contract now; showing them is a progression/economy presentation
  decision this task should not make alone.
