# Phase 5 — AI, Learning, Avatar and Integrations

## Objective
Reduce parent effort and add guided learning without transferring authority to AI.

## Streams
F1 AI Gateway, F2 Knowledge Base/Development Profile, F3 parent assistant/task generation, F4 avatar, F5 learning sessions, F6 Alice, F7 Telegram, F8 MAX, F9 MCP.

## Mechanics
AI task/quest plans; age-based suggestions; source/evidence display; parent approval; child learning sessions; word/rule practice through voice; orthography feedback; avatar creation; status/notifications through supported integrations.

## Evidence
Learning results update versioned Development Profile evidence. Recommendations must expose their evidence basis and remain parent-controllable.

## Alice
Design around account linking, device binding and a server-authorized task/learning interface. The skill must not expose unrelated child data or money state.

## Integrations
Adapters consume canonical domain APIs/events. They never implement task/reward logic independently. Capability gaps require an explicit fallback.

## Contract gate
AI tool schemas, evidence model, avatar policy, external identity/device binding and integration permissions freeze before end-to-end adapter work.

## Exit
Parent can generate, inspect and approve a plan; child can complete one AI-assisted learning session; avatar is safe and reusable; at least one Alice/Telegram/MAX journey works end-to-end with scoped permissions and explainable learning evidence.
