# Coverage Audit — discussion to repository

## Purpose
Map discussed product mechanics to authoritative docs and expose gaps before implementation.

## Covered well
- family, parent/child roles and core permissions
- task/verification model and media evidence
- XP, coins, money ledger, coupons, streaks
- camera pose overlay and deterministic exercise counting
- separate parent/child/family social graphs
- child messenger and parent visibility modes
- parent chat, moderation and reporting
- AI gateway, knowledge base and human approval
- Alice, Telegram, MAX and MCP adapter direction
- modular monolith, event model, realtime, storage and CI
- AI team, gates, discovery/rework and phase planning

## Gaps identified and now added
- Family lifecycle and second-parent invitation contract
- Task Builder DSL and Rules Engine contract
- composite tasks, scenarios and progression rules
- parent social discovery, family matching and case sharing
- child competition/fairness model
- learning/development profile and evidence provenance
- AI avatar lifecycle and child-data safeguards
- platform/device matrix and capability policy
- integration account/device linking
- explicit phase handoff contracts and parallel-stream sync points
- fuller Phase 0/1/2/4/5/6 task backlog

## Deliberately deferred
- production payment rail
- open child discovery
- public child communities
- full game platform runtime
- advanced AI automatic task verification beyond exercises

## Audit rule
A capability is not considered designed merely because its name exists in the domain map. It needs an owning document, contract, acceptance path and phase/task linkage.
